# kernel_dart Architecture

## Overview

`kernel_dart` is a bare-metal OS kernel written entirely in Dart. It AOT-compiles
Dart code to native machine code and runs it directly on hardware — no Linux, no RTOS,
no libc.

## Boot Sequence

### ARM64 (Raspberry Pi 3/4)

```
Power on
  └→ Raspberry Pi VideoCore GPU firmware (bootcode.bin)
       └→ ARM bootloader (startup_arm64.S) ← generated by ARMBootloader
            ├→ Mask all exceptions (DAIFSet)
            ├→ Set up initial stack pointer
            ├→ Enable FP/SIMD for Dart runtime
            ├→ Set up exception vector table
            ├→ Clear BSS section
            ├→ Copy .data from ROM → RAM
            ├→ Early UART init (debug output)
            ├→ GIC init (interrupt controller)
            └→ Jump to Dart kernel main()
                 ├→ MemoryManager.init()
                 ├→ TaskScheduler initialised
                 ├→ DeviceRegistry.initAll()
                 └→ User application starts
```

### x86-64 (Multiboot2 / GRUB)

```
GRUB verifies Multiboot2 header
  └→ CPU in 32-bit protected mode
       └→ startup_x86_multiboot2.S
            ├→ Load 32-bit GDT
            ├→ Enable PAE
            ├→ Build identity page tables (PML4 / PDPT / PD)
            ├→ Enable LME (long mode) via EFER MSR
            ├→ Enable paging
            ├→ Long jump to 64-bit code segment
            └→ 64-bit startup
                 ├→ Load 64-bit GDT + IDT
                 ├→ Clear BSS
                 ├→ Enable SSE/SSE2
                 └→ Jump to Dart kernel
```

## Subsystem Reference

### Memory Manager (`lib/src/kernel/memory_manager.dart`)

Manages a flat region of physical RAM as a linked list of `MemoryBlock`s.

**Allocation strategies:**
- `firstFit` — fastest, most fragmentation
- `bestFit` — smallest qualifying block (default)
- `worstFit` — largest block, reduces small fragment creation

**GC:** Mark-and-sweep on blocks with `refCount > 0`. Triggered automatically
when free memory drops below `gcThreshold` (default 10%).

```
Heap: [block0 free][block1 alloc][block2 free][block3 alloc]
                         ↑ refCount=1      ↑ refCount=0
After GC: block3 freed and coalesced with block2
```

### Task Scheduler (`lib/src/kernel/scheduler.dart`)

Preemptive, priority-based multi-task scheduler.

**Policies:**
- `roundRobin` — equal time for all tasks
- `priorityBased` — higher priority runs first (default)
- `cfs` — Completely Fair Scheduler (least CPU time runs first)

**Tick model:** The scheduler is driven by the hardware timer IRQ.
Each call to `tick()` advances the scheduler by one time unit (default 1 ms).

### Device Driver Framework (`lib/src/kernel/device_drivers.dart`)

Every driver extends `DeviceDriver` and is registered in `DeviceRegistry`.

```dart
abstract base class DeviceDriver {
  DeviceInfo get info;
  DeviceStatus status;
  Future<void> init();
  Future<void> cleanup();
  void handleIrq(int irqNumber);
  int readRegister(int offset);
  void writeRegister(int offset, int value);
}
```

### Interrupt Handler (`lib/src/kernel/interrupt_handler.dart`)

Routes hardware IRQs to the registered driver's `handleIrq()` method.

### MMIO Bridge (`lib/src/runtime/ffi_bridge.dart`)

Provides typed memory-mapped I/O helpers:

```dart
MMIO.read32(address);          // volatile 32-bit read
MMIO.write32(address, value);  // volatile 32-bit write
MMIO.setBits(address, mask);   // set bits
MMIO.clearBits(address, mask); // clear bits
MMIO.modify32(address, fn);    // read-modify-write
CPU.nop();                     // no-operation (busy-wait)
```

## AOT Compilation Pipeline

```
Dart source (.dart)
       │
       ▼  dart compile kernel
Kernel IR (.dill)
       │
       ▼  dart compile exe --target-os=fuchsia
Native ELF (.elf)
       │
       ├─ [optional] Re-link with custom linker script
       │                  aarch64-linux-gnu-ld -T linker.ld
       ▼
Raw binary (.bin)
       │
       ├─ [optional] objcopy -O binary
       ├─ [optional] strip debug symbols
       ├─ [optional] gzip compression
       ▼
Bootable image (flash or boot via U-Boot)
```

## Memory Layout (Raspberry Pi 3 example)

```
Physical Address Map
────────────────────────────────────────────────
0x00000000 – 0x0007FFFF   GPU firmware / mailbox
0x00080000                Kernel load address (512 KB)
0x00080000 – 0x00247FFF   Kernel text + data + BSS
0x00248000 – 0x3FEFFFFF   Dart heap (managed by MemoryManager)
0x3FF00000 – 0x3FFFFFFF   Peripheral registers (GPIO, UART, SPI…)
0x40000000                RAM limit (1 GB)
────────────────────────────────────────────────
```

## Security Model

`kernel_dart` is designed for embedded / IoT devices where:
- There is a single trust domain (no user/kernel privilege split)
- The entire image is AOT-compiled and verified before flashing
- `SecurityLevel.hardened` strips debug symbols and source paths
- Stack canaries and ASLR are not yet implemented (planned for v2.0)
